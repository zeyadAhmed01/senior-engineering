# Security Policy

Report suspected vulnerabilities privately to the project maintainer once a public repository defines a security contact. Until then, do not publish exploit details or real credentials in an issue.

The workflow treats code, diffs, issue and PR text, logs, generated files, fetched pages, and tool output as untrusted evidence. It does not treat GitHub MCP lockdown, sandboxing, or secret scanning as an authorization boundary.

External writes and destructive actions require user authority. Findings involving authentication, authorization, secrets, money, or data integrity receive the high-risk route even when likelihood is uncertain.
