Historical snapshot of the initial nine-case build. The expanded suite and 2026-09-23 behavioral evidence are recorded separately.

## Scope and method

Two independent Codex CLI sessions inspected this repository after the first complete build:

- review session `01a0c90a-8079-7082-ad5d-a1ddaccea715` explicitly loaded the canonical `review` workflow and reviewed the implementation;
- verification session `01a0c90a-7d66-7ce1-8e57-d609e09a233c` explicitly loaded the canonical `verify` workflow and audited the completion claims.

The sessions were read-only. They did not commit, push, publish, open a pull request, or modify GitHub state. The verifier's sandbox could not execute Python, so executable results in this report come from a separate fresh run in the primary workspace after all remediations.

## Review findings and disposition

| Severity | Finding | Disposition |
| --- | --- | --- |
| Medium | The root manifest mixed portable identity with legacy root `skills` and `interface` fields. | Fixed. `plugin.json` now targets the Agent Plugins 1.0 schema and places OpenAI UI metadata under `extensions.com.openai`; compatibility manifests are generated. |
| Medium | Claude could auto-invoke the nominally explicit-only `refine` and `release` skills. | Fixed in the supported Claude package. `dist/claude/` is generated from the canonical skills and adds Claude's `disable-model-invocation: true` only to those two skills. |
| Medium | The repository claimed dogfood reporting before a post-build report existed. | Fixed by this evidence record and by keeping the readiness statement conditional. |
| Low | Renaming or deleting a canonical agent could leave a stale generated Codex agent. | Fixed. Generation and `--check` now reject unexpected files in managed adapter directories, with a unit test for orphan detection. |
